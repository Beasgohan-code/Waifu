# Deployment checklist (not yet verified)

This is a deployment **plan**, not a claim that SUMMON is deployed or production-ready. Test the gates in [TESTING.md](TESTING.md) and review [migration/backup](MIGRATION_BACKUP.md) before using real users.

## 1. Credentials and isolation

- If the audited upstream is still running, immediately disable its unsafe `/mongobackup` command, restrict database network and account access, and inspect access logs. Treat all historically committed tokens, API hashes, database credentials, image-host keys and session files as exposed. The authorized owner must rotate or revoke each applicable credential/session and coordinate history cleanup; this has **not** been done by this session. Do not paste secrets into chat, commands sent to Telegram, Git, screenshots, logs or support tickets.
- Provision a fresh bot token, high-entropy session secret (at least 32 characters; generate it in a secret manager), explicit operator IDs, and a **new dedicated** MongoDB replica set or sharded cluster. Configure encrypted transport, least-privilege accounts, private networking and backups. Store all values in a secret manager or a private `.env`, never in the frontend. Review MongoDB's [production notes](https://www.mongodb.com/docs/manual/administration/production-notes/) for supported versions and host kernels; its documented TCMalloc incompatibility affects Linux 6.19 through 7.0.13, and MongoDB recommends upgrading the kernel. The disposable CI allocator setting is not a production deployment recommendation.
- Install Python 3.11+ and Node 22+. Use the separate pinned uv bootstrap and `uv sync --locked --extra dev` described in the [README](../README.md) for development/tests, and `npm ci` in `web`. For a dedicated production environment, install from the same lock without dev tools or an editable package: `.bootstrap/bin/uv sync --locked --no-editable --python 3.11 --no-python-downloads`. Verify the chosen interpreter and platform before release. Plain pip installation from `pyproject.toml` does **not** enforce `uv.lock`.
- The lock records runtime/dev distribution hashes; the project build backend is pinned with build hashes. uv 0.13.7's build-hash enforcement is experimental: source builds requiring other, unpinned build dependencies fail closed. Review and add suitable build constraints/hashes for a new platform instead of disabling verification. A clean locked install has only been tested on Linux x86-64/Python 3.11 here, not on every platform. The separately bootstrapped uv/pip tools and operating-system packages still need their own review and updates. Re-audit dependencies at release. Do not co-install Kurigram, Pyrogram or Pyrofork with Wzgram; `SUMMON_RICH_ENABLED=false` disables its connection, not its installation.
- Copy `.env.example` to a private runtime environment. Set `SUMMON_ENVIRONMENT=production`, `SUMMON_PREVIEW_MODE=false`, `SUMMON_BOT_TOKEN`, `SUMMON_SESSION_SECRET`, `SUMMON_MONGO_URI`, `SUMMON_MONGO_DATABASE`, and the public HTTPS `SUMMON_WEBAPP_URL`. Production settings now reject an empty or non-HTTPS Mini App URL before startup; URL/origin checks also reject whitespace, controls, backslashes and malformed hosts. They do not prove that DNS, TLS, Telegram reachability or the reverse proxy works. Rendered settings-validation errors hide input values, but structured errors may still contain them: never log raw validation data. `SUMMON_OPERATOR_IDS` is a JSON list on the **server**, with no default operators. Supply `SUMMON_TELEGRAM_API_ID` and `SUMMON_TELEGRAM_API_HASH` only when opting into `SUMMON_RICH_ENABLED=true` for outbound Wzgram. Native Bot API rich messages are separately controlled by `SUMMON_BOT_API_RICH_ENABLED` and need no MTProto credentials.
- Startup pings MongoDB and checks that `hello` (or legacy `isMaster` on an explicit unknown-command response) reports sessions, a supported wire version and a writable replica primary, mongos or explicitly configured load-balanced connection. Unsupported topologies fail before schema changes. This does **not** prove transactions, majority/linearizable reads, permissions or failover work. Startup then creates/updates validators and indexes, including `collMod` for matching existing collection names. Confirm the dedicated target and required privileges before first launch; never point SUMMON at a legacy/shared database without a separate compatibility and migration plan.
- Leave `web_sessions` unsharded, synchronize API-worker and MongoDB clocks, and use the same bot token, session secret and authentication-age settings on every API worker. The nonce TTL includes a small clock-skew/final-second buffer but cannot compensate for unbounded skew or inconsistent age settings. Verify the actual cluster supports bounded primary linearizable reads and majority writes with appropriate durability/journaling. Every authenticated request reads the session record; loss of a primary/majority can cause 503s and linearizable reads may add substantial latency. Test that behavior, revocation and failover on the intended topology before deployment.

## 2. Telegram and frontend

- Configure the HTTPS Mini App URL for the bot using Telegram's current BotFather flow. Open `/start` in a private chat to receive its Mini App button. The Mini App home view can offer a Telegram-native collection shortcut on compatible clients; regular navigation remains available. Configure `SUMMON_PREMIUM_EMOJI_ENABLED` consistently for bot and API processes; set it to `false` for Unicode labels. The API bootstrap exposes only the public shortcut glyph/ID, not credentials. Neither the flag nor a successful mock proves pack rights, Telegram entitlement or live rendering. Install the bot in a test group; activity and protection need Telegram to deliver the relevant new and edited messages (check privacy mode, roles and update types). Grant only needed delete/restrict privileges; each action still rechecks rights. Anonymous/channel senders, bots, service events and nested rich content have coverage limits described in [architecture](ARCHITECTURE.md).
- A group administrator uses `/manage` to link the group and may use `/spawns on` or the Mini App to opt into spawns. The Mini App can also enable a rate-limited goodbye notice (off by default and triggered by leaves or removals). Character catalogue entries are required. No real catalogue is auto-imported. Telegram must be able to fetch the artwork: `/art/` paths resolve against the configured public `SUMMON_WEBAPP_URL`, and external artwork must be publicly reachable over HTTPS. Definite artwork rejection cancels the spawn rather than sending a text-only guessing challenge; inspect delivery-failure logs. An ambiguous network result can leave a reservation active until expiry.
- Public group notes require an initialized group (`/manage`), a live `can_change_info` check for administrators, and a current member lookup for `/notes` or `/note`. Telegram only guarantees other-user membership lookups when the bot is an administrator; test the intended role and privacy-mode behavior. Notes are visible in the group and may be forwarded; do not store credentials or private information in them. Check current content and activity before retrying uncertain writes. Note text is not retained in the audit log after deletion.
- Optional sample content: run `summon-seed` to see a no-connection plan. After checking the exact dedicated target and obtaining operator approval, `summon-seed --apply --confirm INSERT-SAMPLE` inserts missing `aiko`, `ren`, `mira` only. Existing IDs and all inventory remain untouched. The apply path also initializes database validators/indexes. Original example illustrations in `web/public/art` are optional sample assets, not imported user data.
- Build the frontend with `cd web && npm ci && npm run build`. Host `web/dist` on the same HTTPS origin as `/api` and `/art`, with SPA fallback for static routes. Reverse proxy `/api` and health endpoints to FastAPI and forward `X-Summon-Launch` and `X-Summon-Request` unchanged; do not cache API responses. The browser uses relative URLs, same-origin cookies and Web Crypto in a secure context; it does not call a browser-local backend. Do not expose Vite's permissive development server as production hosting.
- Upgrading from earlier unbound or stateless cookies invalidates those sessions: ask users to reopen the Mini App in Telegram for a fresh launch. A different Telegram launch sharing the same cookie jar replaces the cookie; older tabs fail closed and may require reopening. Logout revokes the current server-side session but cannot cancel requests already authorized. If sign-in fails after consuming its one-time launch proof, reopening may be necessary.

## 3. Processes and proxy

- Run **one** `summon-bot` process for the token. It removes any existing webhook (without dropping queued updates) and then polls; coordinate any cutover to avoid a second poller or webhook. Optional Wzgram has `no_updates=True` and registers no handlers. Run one or more `summon-api` workers separately.
- The convenient `summon-api` entry point binds `0.0.0.0:8000`. Firewall the API and put it behind a TLS reverse proxy; alternatively bind Uvicorn to a private interface. Restrict Host values at the proxy, preserve the public Host/scheme for Origin checks, and trust forwarded headers **only from known proxy addresses**. For a same-host proxy, an explicit loopback-only Uvicorn `--forwarded-allow-ips` policy is appropriate; adapt to the actual topology, never blindly trust arbitrary internet clients.
- Enforce request-size limits, read and authentication abuse/rate limits, secure TLS, sensible timeouts and sanitized access logs at the proxy. `summon-api` disables Uvicorn's raw-path access log; if launching Uvicorn directly, use `--no-access-log` or equivalent redaction. The application logs route templates rather than concrete IDs. The application has Mongo-backed auth and mutation limits, not a complete DDoS or read-rate limiter. `SUMMON_ALLOWED_ORIGINS` must contain exact browser-serialized HTTPS origins in production: lowercase host, punycode for international domains, no path or default port (for example, `https://example.com`, not `https://EXAMPLE.com:443`). Existing noncanonical entries must be corrected before upgrading. The bundled frontend is designed for same-origin deployment; setting CORS alone does not make its cookie requests cross-origin.
- Check `/health` (liveness) and `/health/ready` (Mongo ping plus read-only topology check) through internal monitoring. Both being green does **not** prove a transaction, session lookup, permissions, failover, Telegram delivery, callbacks or user workflows. Preview/injected responses are not database readiness. Alert on transaction errors, failed session lookups, failed Telegram delivery, partial moderation actions, uncertain warning corrections and storage/backup failures. Do not log signed launch data, launch headers, signed session cookies or credentials; cookies are signed, not encrypted. Warning reasons and actor/target IDs are sensitive; restrict database/backups and redact group/member/warning identifiers from proxy access logs as appropriate.
- The warning-review upgrade adds an index, keeps existing warning records, and treats missing `revoked_at` as active. Old app instances still count revoked warnings and expose the prior moderation activity feed to non-restrict admins. Coordinate deployment so old and new versions do not concurrently serve the same groups, and plan rollback before any downgrade. On an uncertain correction, inspect warning/audit state before retrying. No real upgrade has been exercised here.
- Public notes add an optional `saved_notes_v1` group-document field and change the group validator at startup. Confirm the reserved field is absent or compatible in the dedicated target, take an authorized backup and test the validator and transactions on an isolated replica set first. Do not delete or overwrite an unexpected existing field. Older binaries can reapply an earlier validator on startup and do not offer the notes workflow; coordinate rollout/downgrade and retain note data. Monitor note transaction conflicts/uncertain writes, especially in busy groups, and test the actual MongoDB implementation rather than assuming wire-compatible services support its validation keywords.
- Opt-in public auto replies add the optional `auto_replies_v1` field and update the group validator. Check the reserved field for compatibility, back up the authorized target, and rehearse validator/transaction changes on an isolated replica set before rollout; never delete or overwrite unexpected existing data. Coordinate mixed versions because older binaries can reapply older validators and will not send these replies. Message delivery depends on Telegram privacy mode, current rights, and the shared `rate_limits` TTL index; majority-acknowledged hashed claims suppress replays for at least 48 hours while retained, not exactly-once delivery. Monitor storage latency, rate/claim failures and group-document transaction contention. A queued/in-flight message can still use a rule snapshot read before it was disabled. Triggers and replies are public; inspect state before retrying uncertain changes.
- Collection copy-count sorting adds an index on `(user_id, quantity DESC, character_id)`. Startup creates it on the authorized dedicated database; this is a write and may consume resources on existing inventory. Rehearse index creation and query performance before rollout. The filter and sort do not change quantities or ownership.

## 4. Before cutover

Rehearse schema initialization, concurrent catch/trade/gift/daily races, transaction rollback, role revocation, real rich/emoji/ephemeral delivery, failover, backups and isolated restore with a test bot and replica set. Document outcomes and recovery ownership. No existing data is imported automatically; follow the separate migration plan. Expand group features only after tests and explicit authorization. Release remains blocked until these gates pass.
